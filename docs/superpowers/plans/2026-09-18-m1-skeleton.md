# canopy M1 Implementation Plan: Skeleton, Ownership & Restore

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A canopy install that can be placed onto a machine with pre-existing configs and removed again, returning every pre-existing file to its exact original bytes, proven in CI.

**Architecture:** Pure POSIX shell plus tmux configuration. A dispatcher (`bin/canopy`) routes to one-command-per-file scripts (`bin/canopy-*`) that carry metadata headers. Shared behaviour lives in `lib/*.sh`, sourced, never duplicated. Every mutating command opens a transaction that byte-captures what it is about to change, so `restore` is a replay of a ledger rather than a best-effort guess.

**Tech Stack:** POSIX sh (`/bin/sh`, no bashisms in `lib/` or `bin/`), tmux ≥ 3.4, bats-core for tests, shellcheck + shfmt for lint, GitHub Actions for CI.

**Spec:** `docs/superpowers/specs/2026-09-17-canopy-design.md`

## Global Constraints

Copied verbatim from the spec. Every task's requirements implicitly include these.

- **POSIX sh only** in `bin/` and `lib/`. No bash-only syntax (`[[`, arrays, `local` is permitted as it is universally supported by dash/ash/bash in practice, but nothing else). Test scripts may use bash (bats requires it).
- **tmux ≥ 3.4** is the floor. `source-file` glob support is required and verified present in 3.7b.
- **We never write a file we don't own, and ownership is provable.** A file is ours only if it is a symlink into our store, carries our marker block, or is a generated file whose recorded hash still matches.
- **Preference order for touching another app's config:** drop a new file into an extension point → own a whole file with a backup → splice into someone else's file (last resort, marker-delimited, rewritten only between markers).
- **The pre-install restore point is complete and reachable forever.** `canopy restore --all` returns every file that existed before canopy to its exact original bytes.
- **A migration may not write to a user-owned file.** If it must, it opens a config transaction instead.
- **No identity in shipped files:** no hostnames, emails, client names, machine specifics. Personal content lives in `~/.config/canopy/`, never in the store.
- **canopy never installs system packages.** It declares and diagnoses only.
- **Capability detection happens once**, at install/update/doctor, never at config load and never in a render path.
- Paths: store `~/.local/share/canopy`, user config `~/.config/canopy`, state `~/.local/state/canopy`, runtime `${XDG_RUNTIME_DIR:-/tmp}/canopy`. All are overridable by `CANOPY_STORE`, `CANOPY_CONFIG`, `CANOPY_STATE`, `CANOPY_RUNTIME`; **tests depend on this**, so no path may be hardcoded anywhere.

- [ ] **Step 3: Implement `lib/env.sh`**

```sh
# shellcheck shell=sh
canopy_paths() {
  : "${CANOPY_STORE:=$(cd "$(dirname "$0")/.." && pwd)}"
  : "${CANOPY_CONFIG:=${XDG_CONFIG_HOME:-$HOME/.config}/canopy}"
  : "${CANOPY_STATE:=${XDG_STATE_HOME:-$HOME/.local/state}/canopy}"
  : "${CANOPY_RUNTIME:=${XDG_RUNTIME_DIR:-/tmp}/canopy}"
  export CANOPY_STORE CANOPY_CONFIG CANOPY_STATE CANOPY_RUNTIME
}

canopy_have() { command -v "$1" >/dev/null 2>&1; }

canopy_sha256() {
  if canopy_have sha256sum; then sha256sum "$1" | cut -d' ' -f1
  elif canopy_have shasum; then shasum -a 256 "$1" | cut -d' ' -f1
  else canopy_die "no sha256 tool found (need sha256sum or shasum)"; fi
}

canopy_die() { printf 'canopy: %s\n' "$1" >&2; exit 1; }
```

Note: `${XDG_CONFIG_HOME:-...}` treats an empty value as unset, which the second test depends on.

## Task 3: `lib/manifest.sh` (transactions)

**Files:**
- Create: `lib/manifest.sh`, `test/manifest.bats`

**Interfaces:**
- Consumes: `lib/env.sh` (`canopy_sha256`, `canopy_paths`, `canopy_die`).
- Produces:
  - `canopy_tx_begin <label>`: creates `$CANOPY_STATE/backups/<epoch>-<label>/`, prints its path, writes `manifest.tsv` header and a copy of `restore.sh`.
  - `canopy_tx_record <txdir> <action> <path>`: action ∈ `own|splice|drop|generate|env`. Captures pre-state: if the path exists, copies it to `<txdir>/files/<mangled>` and records its sha256; otherwise records `absent`.
  - `canopy_tx_commit <txdir>`: records each path's post-state sha256, marks the transaction complete.
  - Manifest format, tab-separated: `action<TAB>path<TAB>pre(absent|sha256)<TAB>backup_rel(-|path)<TAB>post(sha256|absent)`.

- [ ] **Step 1: Write the failing tests**

`test/manifest.bats`:
```bash
#!/usr/bin/env bats
load helper
setup() {
  setup_canopy_env
  . "$CANOPY_STORE/lib/env.sh"; . "$CANOPY_STORE/lib/manifest.sh"
  canopy_paths
  target="$BATS_TEST_TMPDIR/target.conf"
}

@test "records an existing file with its pre-hash and a byte copy" {
  printf 'original\n' > "$target"
  tx="$(canopy_tx_begin install)"
  canopy_tx_record "$tx" own "$target"
  printf 'replaced\n' > "$target"
  canopy_tx_commit "$tx"
  grep -q "own	$target	" "$tx/manifest.tsv"
  backup="$(awk -F'\t' -v p="$target" '$2==p {print $4}' "$tx/manifest.tsv")"
  [ "$(cat "$tx/$backup")" = "original" ]
}

@test "records an absent file as absent" {
  tx="$(canopy_tx_begin install)"
  canopy_tx_record "$tx" drop "$BATS_TEST_TMPDIR/new.conf"
  printf 'new\n' > "$BATS_TEST_TMPDIR/new.conf"
  canopy_tx_commit "$tx"
  [ "$(awk -F'\t' '{print $3}' "$tx/manifest.tsv" | tail -1)" = "absent" ]
}

@test "every transaction ships a self-contained restore.sh" {
  tx="$(canopy_tx_begin install)"
  [ -x "$tx/restore.sh" ]
  grep -qv 'canopy_' "$tx/restore.sh"   # must not call into the store
}
```

- [ ] **Step 3: Implement `lib/manifest.sh`.** Path mangling for backup filenames: replace `/` with `%`. `restore.sh` is written from a heredoc and reads only `manifest.tsv` + `files/` relative to its own directory; it must not source anything from the store (the test asserts this).

## Task 8: `bin/canopy-install`

**Files:**
- Create: `bin/canopy-install`, `test/install.bats`

**Interfaces:**
- Consumes: `lib/env.sh`, `lib/manifest.sh`, `lib/tmux.sh`, `bin/canopy-caps`, `bin/canopy-index`.
- Produces: an install transaction labelled `install`, marked **pinned** (`touch "$tx/.pinned"`), which:
  1. If a user tmux config exists (`$XDG_CONFIG_HOME/tmux/tmux.conf` or `~/.tmux.conf`): record it (`own`), copy its contents to `$CANOPY_CONFIG/user.conf` (appending, with a marker comment naming the original path and date), then replace it with a file that sources the store's `tmux/tmux.conf`.
  2. Write `$CANOPY_CONFIG/user.conf` if it did not exist (empty, with a comment header).
  3. Write `~/.config/mise/conf.d/canopy.toml` (action `drop`) declaring canopy's tools, **only if** `~/.config/mise/conf.d/` exists or mise is present; skipped silently otherwise.
  4. Run `canopy-caps` and `canopy-index`.
  5. `canopy_tmux_validate` the resulting config; on failure, abort and roll the transaction back before exiting non-zero.
- `--dry-run` prints every action it would take, touching nothing. **A first run that detects an existing tmux config prints the plan and requires `--yes` to proceed**, because owning someone's tmux.conf is a migration, not a merge.

## Task 9: `bin/canopy-restore`

**Files:**
- Create: `bin/canopy-restore`, `test/restore.bats`

**Interfaces:**
- Consumes: transaction manifests (Task 3).
- Produces:
  - `canopy restore`: roll back the newest transaction.
  - `canopy restore --list`: one line per transaction: id, label, timestamp, file count, `PINNED` marker.
  - `canopy restore --to <id>`: roll back every transaction newer than, and including, `<id>`.
  - `canopy restore --all`: roll back to the pinned pre-install point.
  - `--force`: proceed despite post-state hash mismatches.
- Rules: a path whose current hash differs from the recorded post-state means the user edited it after canopy wrote it: **refuse, name the file, exit non-zero**, unless `--force`. Restore opens its own transaction first. `$CANOPY_CONFIG` is never removed. Files recorded as `absent` are deleted only when their current hash still matches the recorded post-state. Restore ends by printing reverted / kept counts and the location of anything kept.

- [ ] **Step 1: Write the failing tests**

```bash

  tx="$(canopy_tx_begin install)"; touch "$tx/.pinned"
  canopy_tx_record "$tx" own "$target"
  printf 'canopy-owned\n' > "$target"
  canopy_tx_commit "$tx"
  run canopy restore --all
  [ "$status" -eq 0 ]
  [ "$(canopy_sha256 "$target")" = "$orig" ]
}

@test "restore refuses a file edited after install, and says which" {
  # ... same setup, then:
  printf 'my later edit\n' > "$target"

}

  printf 'my later edit\n' > "$target"

  grep -rq 'my later edit' "$CANOPY_STATE"/backups/*/files/
}

@test "a dropped file is deleted only if unmodified" {
  # absent pre-state + matching post hash → deleted
  # absent pre-state + changed content → kept, reported
}

@test "restore never removes the user config dir" {
  echo x > "$CANOPY_CONFIG/user.conf"
  canopy restore --all
  [ -f "$CANOPY_CONFIG/user.conf" ]
}
```
